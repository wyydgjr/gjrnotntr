# 简易电商平台 — 部署说明

> 环境要求：Windows / Linux / macOS 均可；Node.js >= 18、MySQL 8.0+。

## 一、项目结构总览

```
实训/
├── docs/
│   ├── 数据库设计文档.md          # 数据库设计（ER图/表结构/约束）
│   ├── database.sql               # 建库建表 + 示例商品 SQL（5 张表）
│   ├── API接口文档.md             # 全部接口说明与示例
│   ├── swagger.json               # OpenAPI 3.0.3 接口描述（38 个接口，可导入 Swagger UI / Apifox）
│   ├── postman_collection.json    # Postman Collection v2.1（6 个分组，登录后自动回写 token）
│   └── 部署说明.md                # 本文档
├── backend/                       # 后端源码（Express + MySQL + JWT）
│   ├── simple-server.js           # 极简版后端（单文件，端口 3001，答辩对照用）
│   └── src/
│       ├── server.js              # 启动入口（随服务拉起订单超时定时任务）
│       ├── app.js                 # Express 应用装配（含 /api/health 健康检查）
│       ├── config/db.js           # MySQL 连接池
│       ├── middleware/            # auth.js（JWT + RBAC）、errorHandler.js
│       ├── routes/                # index / auth / product / order / address / stats（37 条业务路由）
│       ├── controllers/           # auth / product / order / address / stats 控制器
│       ├── services/              # orderExpireService.js、orderExpireTask.js（订单超时自动取消）
│       └── utils/                 # response.js、jwt.js、asyncHandler.js
└── frontend/                      # 前端源码（Vue3 + Vite + Element Plus）
    ├── .env                       # VITE_API_BASE 接口地址配置
    └── src/
        ├── api/                   # request.js（axios 实例 + 拦截器）、index.js（业务接口封装）
        ├── router/                # 路由与登录 / 角色守卫
        ├── stores/                # user.js（登录态）、cart.js（购物车，localStorage 持久化）
        ├── layout/                # MainLayout.vue（侧边栏 + 顶栏）
        └── views/                 # Login / Register / Dashboard / Shop /
                                   #   product（列表 + 详情）/ order（管理 + 我的订单）
                                   #   address（收货地址）/ settings（个人设置）
```

## 二、本地部署步骤（推荐）

### Step 1：初始化数据库

```bash
# 登录 MySQL 后执行建库建表脚本
mysql -u root -p < docs/database.sql
```

检查是否成功：

```sql
USE ecommerce;
SHOW TABLES;   -- 应看到 users / products / orders / order_items / addresses 共 5 张表
```

### Step 2：启动后端

```bash
cd backend
npm install

# 复制环境变量模板（Windows: copy .env.example .env）
cp .env.example .env

# 编辑 .env，将 DB_USER / DB_PASSWORD 改为本机 MySQL 账号密码

# 初始化默认账号（admin/admin123，user/user123）
npm run seed

# 启动服务（开发模式，nodemon 热更新）
npm run dev
```

后端启动成功提示（两行分别来自 `backend/src/server.js` 与 `backend/src/services/orderExpireTask.js`）：

```
[ecommerce-backend] server running at http://localhost:3000
[order-expire] 定时任务已启动：每 60 秒扫描一次，支付超时阈值 30 分钟
```

自测：

```bash
curl http://localhost:3000/api/health
# {"code":0,"message":"success","data":{"status":"ok",...}}
```

### Step 3：启动前端

```bash
cd frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:5173`，使用默认账号登录：

| 账号 | 密码 | 角色 | 可见功能 |
|---|---|---|---|
| admin | admin123 | 管理员 | 统计看板、商品管理、订单管理 |
| user | user123 | 普通用户 | 商品商城、我的订单 |

> 开发环境前端已通过 Vite 代理将 `/api` 转发到后端 3000 端口，无需额外配置跨域。

**`frontend/.env` 中 `VITE_API_BASE` 配置说明：**

| 配置文件 | 取值 | 适用场景 |
|---|---|---|
| `frontend/.env.example` | `VITE_API_BASE=/api` | 开发模式（`npm run dev`），走 Vite 代理转发到 3000 端口 |
| `frontend/.env` | `VITE_API_BASE=http://localhost:3000/api` | 打包成单文件后从 `file://` 直接打开，无代理可用，必须指向后端完整地址 |

> Vite 只在启动 / 构建时读取环境变量，修改 `.env` 后需重启 `npm run dev` 或重新 `npm run build` 才生效。

## 三、常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 后端启动报 `ER_ACCESS_DENIED_ERROR` | `.env` 中 DB_USER / DB_PASSWORD 与本机 MySQL 不一致 |
| 后端报 `ER_BAD_DB_ERROR: Unknown database 'ecommerce'` | 未执行 Step 1，或执行 SQL 时未指定正确的库 |
| 登录提示"用户名或密码错误" | 未执行 `npm run seed` 创建默认账号 |
| 前端 401 循环跳登录页 | 后端未启动或 token 已过期，重新登录即可 |
| 前端接口 500 | 查看后端终端错误日志（错误细节只在服务端打印） |

## 四、收货地址模块与订单超时任务说明

### 4.1 收货地址模块 `/api/addresses`

- 数据表：`addresses`（`user_id` / `receiver` / `phone` / `address` / `is_default`），与 `users` 一对多，用户删除时级联清理；
- 接口 5 条（均需登录，只能操作自己的地址）：`GET /api/addresses` 列表、`POST /api/addresses` 新增、`PUT /api/addresses/{id}` 修改、`DELETE /api/addresses/{id}` 删除、`POST /api/addresses/{id}/default` 设为默认；
- 校验规则：单用户最多 20 条地址，手机号需匹配 `^1\d{10}$`；设置默认地址时先把该用户其它地址 `is_default` 清零再置一；
- 与订单的关系：地址簿只作为下单时的选择来源，收货人 / 电话 / 地址仍以快照写入 `orders`，地址后续修改不影响历史订单。

### 4.2 订单超时自动取消定时任务

- 代码位置：`backend/src/services/orderExpireService.js`（业务逻辑）+ `backend/src/services/orderExpireTask.js`（调度）；
- 启动方式：`backend/src/server.js` 在 `app.listen` 回调中调用 `startOrderExpireTask()`，服务启动 5 秒后先跑一次，之后每 60 秒扫描一次；
- 超时阈值：`PAY_TIMEOUT_MINUTES` 默认 30 分钟，可用环境变量 `ORDER_PAY_TIMEOUT_MINUTES` 覆盖；扫描间隔可用 `ORDER_EXPIRE_INTERVAL_MS` 覆盖；
- 处理动作：仅处理 `pending` 状态的超时订单，置为 `cancelled` 并在同一事务内回滚 `products.stock`，避免库存被长期占用；
- 手动触发（联调用）：`POST /api/orders/expire-check`（需管理员权限）；
- 稳定性：两个定时器均调用 `unref()`，不阻塞进程退出；任务内部 try/catch，单次执行异常不影响后续调度。

## 五、极简版 demo 启动（答辩对照用）

工程版（端口 3000）与极简版（端口 3001）功能等价，可同时启动，用于答辩时逐接口对比讲原理。

```bash
# 1. 后端：极简版单文件服务（约 450 行实际代码，零分层）
cd backend
node simple-server.js      # 监听 http://localhost:3001

# 2. 前端：直接双击打开极简版页面（原生 JS，零框架零构建）
#    实训\极简版前端.html
```

说明：

- `backend/simple-server.js` 连的是同一个 `ecommerce` 库，接口路径、参数、返回结构与工程版完全一致；
- `极简版前端.html` 右上角内置端口选择器，可在「工程版 3000」与「极简版 3001」之间切换，用同一份页面演示两套后端；
- 两套服务共用同一个数据库，演示时不要用同一账号并发做写操作（如下单），否则会互相影响库存。

## 六、生产部署（可选参考）

以 Linux + Nginx + PM2 为例：

```bash
# 1. 后端：安装 pm2 并托管
npm install -g pm2
cd backend
npm install --production
pm2 start src/server.js --name ecommerce-api

# 2. 前端：构建静态产物
cd frontend
npm install
npm run build        # 生成 dist/

# 3. Nginx 配置：静态资源 + API 反向代理
# /etc/nginx/conf.d/ecommerce.conf
```

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态资源
    root /var/www/ecommerce/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
# 4. 生效配置
nginx -s reload
```

> 生产环境务必修改 `.env` 中的 `JWT_SECRET` 为足够长的随机字符串，并通过环境变量注入数据库账号密码，避免明文入库到代码仓库。
